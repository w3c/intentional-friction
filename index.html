Introduction

User friction in a digital interface creates inaccessibility and accessibility guidance aims to remove this friction to make the interface easy to use for as many people as possible. Some friction, however, is fundamental to the nature of a product or service and removing it can break the system or the user experience rather than enhance it. This Note aims to find a way to identify this 'intentional friction' so that it can be preserved while the unintentional friction that creates unnecessary inaccessibility can be removed.

Types of Intentional friction

There are two main types of intentional friction: generative friction and protective friction. Generative frictionGenerative friction creates value whereas protective friction prevents harm.

Generative Friction

Educational Tools

Educational tools use friction to encourage learning in users. Asking questions and expecting users to remember facts or data creates a memory challenge. Timed quizzes aim to distinguish between effortful retrieval and automatic retrieval (does the user need to work out the answer each time or is the answer itself memorised). This is especially useful in mathematics where automatic retrieval of simple and common calculation answers can free up mental capacity for high-level problem solving.

Bjork and Bjork recommend several ways in which making testing harder can improve learning overall. Spacing out practice sessions to encourage partial forgetting, switching between types of problem, varying learning environments to remove associations between the environment and the subject that would have aided recall, and actively requiring the user to retrieve information from memory before re-presenting facts will all increase friction and make the process harder.

Bjork and Bjork argue that this improves the storage strength of the facts rather than the retrieval strength in the moment. The level of difficulty introduced must, however, be balanced for the user to create a constructive challenge rather than a deterrent challenge.

Video Games

One of the most widely cited definitions of games was created by Jesper Juul. Jesper's definition is based on 6 rules or elements. "A game is 1) a rule-based formal system with 2) variable and quantifiable outcome, where 3) different outcomes are assigned different values, 4) the player exerts effort in order to influence the outcome, 5) the player feels attached to the outcome, and 6) the consequences of the activity are optional and negotiable." By this definition a user experience is only a game if it is effortful and that effort influences the outcome. This requirement for effort constitutes intentional friction.

Additionally, some accessibility features in gaming can make the game accessible while removing both the effort and the ability to influence the outcome. An example is auto-aim, which automatically moves a reticule over the target that needs to be hit or selected. While this enables the player to hit or select the target, it removes the challenge of aiming, which forms part of the gameplay challenge itself.

Protective Friction

CAPTCHAs

CAPTCHAs (Completely Automated Public Turing test to tell Computers and Humans Apart) aim to block malicious automated access to digital resources by presenting challenges that only humans should be able to solve.

See the Inaccessibility of CAPTCHA for more on this topic.

Behavioural Interventions

Some friction is designed to discourage destructive behaviours. Gambling services often incorporate deposit limits and mandatory pauses to discourage unhealthy levels of interaction. This could be considered a form of "Slow Design" which is interfaces that slow down user interations to encourage the user to interact in a more mindful way.

Microboundaries

Microboundaries are interactions that attempt to encourage mindful interactions. Examples are confirmation prompts ("Do you want to continue?") before allowing destructive or ireversible actions. Important and irreversible actions often require a confirmation step ("Do you want to continue?") or a cooling-off period to reduce the likelihood of harm through accidental activation or impulsive decision making.

Adding friction to actions seen as harmful or undesirable is intended to discourage those behaviours.

User Identification

Identification and authentication mechanisms introduce a different kind of intentional friction. An ideal design would create an insurmountable challenge for someone who should not be accessing the resource while creating minimal friction for someone who should.

Focus of this Note

This Note focuses on intentional friction in gaming. In the other forms of intentional friction identified it is generally clear what needs to be preserved. If an effort to make a user identification mechanism allows anyone to claim to be that user then it is clear that the mechanism is broken. Similarly the purpose of CAPTCHAS and behavioural interventions are clear and in reviewing an attempt to make them accessible most people would normally agree on whether the mechanism has been broken or not. Friction in educational tools has a large body of work behind it and the frictions involved have specific aims such as encouraging effortless recall, encouraging mindful interaction or impeding immediate recall to encourage better knowledge storage. Again, when one of these frictions is identified it is generally unambiguous whether an accessibility intervention has broken the friction or not.

In gaming the intentional friction is not the means to an end but is the end itself. In 'Flow: The Psychology of Optimal Experience' Mihaly Csikszentmihalyi talks about this enjoyable 'flow' state as being a state between boredom (from too easy a challenge) and anxiety (from too hard a challenge). Gaming attempts to offer this flow state. The need to balance challenge to the player makes game accessibility a unique use case in terms of intentional friction. This Note will focus on this 'intrinsic' enjoyment from gaming that relies on balancing the challenge to the player. There are also 'extrinsic' motivations available; social status from beating games that are designed to test resiliance and perseverance (to continue to play despite the anxiety of a misaligned difficulty level), trophies that state you have beaten a meta-challenge in a game and e-sports which offer material prizes and social status (that could encourage the player to continue despite the boredom of a misaligned difficulty level).

Although the body of the document is going to focus on gaming it could easily address how to deal with protective friction (of the 6 options we identify later we must preserve the challenge if possible or replace it if not). Similarly, generative friction linked to education should be preserved, replaced or rebalanced. Once the cognitive work has been done for gaming it may be quick and easy to apply it to the other spheres.

Not only would it constitute fundamental alteration of the game which may be considered an unreasonable requirement, but it could actually break the game experience itself.

The perception of difficulty

Ian Hamilton's Difficulty vs Accessibility talk at GAConf USA 2021 highlighted that there is no fixed difficulty for a game. Games present barriers and players have capabilities and the level of difficulty that arises comes from trying to overcome the given barriers with a user's unique set of capabilities. Disabled people will have reduced capabilities in some respect meaning they will face higher difficulty for the same set of presented barriers. Within the talk he states that "Accessibility = avoiding unnecessary mismatch between capability & barrier". Steve Saylor framed this to say that accessibility is a way to bring the difficulty back towards the intended level.

The need to preserve inaccessibility

In the IGDA-GASIG page on how to make games accessible it states: "All games must contain some degree of inaccessibility in order to be a game. There must be some kind of challenge. This necessary inaccessibility varies from game to game. It makes accessibility an optimisation process - thinking about the barriers your game may present, which of those are a necessary part of what makes it fun, and which are not."

Game Accessibility Paradox

In the article Game accessibility course design modules in higher education Thomas Westin describes this as the Game Accessibility Paradox. The author argues that games can be described by a series of strict rules for playing the game which are normative. They can't be changed without fundamentally altering the game and effectively creating a new, different, game. The player interacts with these through game mechanics which are performative. They conclude that the two main approaches for accessibility are removing barriers that aren't needed for core gameplay or creating special games that use a different modality (such as audiogames). They note that a third option is to make modifications that alter the game rules creating a new game.

These examples highlight the need to retain some inaccessible features to preserve the challenge of a game but make no recommendation of a formal process to identify which features need retaining.

Challenge manipulation

Westin offers us three ways to make an accessible game.

  1. Make adjustments that preserve the challenge
  2. Make adjustments that alter the challenge,
  3. Create a bespoke game for a target audience,
Since the game is defined by the core challenge only the first of these provides accessibility to the original game. There is a fourth option:
  1. Make adjustments that remove the challenge,
This may be acceptable where a game has multiple challenges and removing this one still leaves enough challenges to keep players interested. It will, however, diminish the value of the product as a game.

Difficulty calibration

Hamilton, however, makes an important point in that the difficulty level of a challenge is not universal. It is generated by the interaction of the barriers presented and the players capabilities which may be diminished in some dimension by a disability. It will also be affected by familiarity with the game itself and familiarity with the game mechanics used.

This suggests two things:

  1. difficulty settings and gradients may enable players to find their own difficulty threshold or adjust the difficulty to suit them,
  2. The difficulty level of a particular challenge mechanism may be reduced with practice,

While these will not prevent inaccessibility from increasing the difficulty of a game they may allow it to be rebalanced to a suitable level.

Many games have to balance challenge as the user gets used to the game mechanics. They may do this by making particular game loops harder with tougher enemies and higher skill requirements or by subverting the game loop with new weapons and abilities that need to be learned. There may also be recurring short periods of higher designed challenge that may enter the anxiety level of challenge and provide a sense of acheivement when the player beats them even if it takes several attempts (so-called 'boss fights' or 'boss monsters'). These are adjustments to the designed challenge that will affect everybody and are not neccessarily accessibility issues (except where a new weapon or skill introduces new unintentional frictions).

Difficulty gradients

There are some games that adjust the difficulty of the challenge depending on the skill of the user. They may do this by:

  1. matching players in multiplayer games who are judged to have a similar skill level (or similar ranks in a leaderboard),
  2. by adjusting the speed, target size or complexity of the challenge mechanism to balance its designed difficulty based on a player's measured ability, this is known as Dynamic Difficulty Adjustment (DDA),
  3. by adjusting the speed, target size or complexity of the challenge mechanism based on selectable difficulty levels.
These may enable a player to find the optimal experience.

Available accessibility remedies

Once we have identified a challenge mechanism that creates inaccessibility we have a series of actions that we may be able to perform.

  1. Make accessibility related adjustments that preserve the core challenge,
  2. Make accessibility related adjustments that remove the core challenge,
  3. Make accessibility related adjustments that replace the core challenge with another challenge,
  4. Where the inaccessibility increases the difficulty instead of making the challenge unplayable the designed challenge of the mechanism can be automatically reduced to rebalance the experienced difficulty,
  5. Where the inaccessibility increases the difficulty instead of making the challenge unplayable different difficulty options can be offered to rebalance the experienced difficulty,
  6. Where the experienced difficulty is a gradient users may naturally find a suitable level on their own.

When intentional friction prevents play

A common way in which inaccessibility prevents play is in communication barriers. This could be information that is presented audibly, visually, via colour or via written language. <-expand this

In some cases information is carried by the channel of communication and can easily be carried by an additional or alternative channel. For instance the value of the ace of spades playing card is carried by the visual design of the playing card but can also be written using the text "Ace of Spades", or the characters "A♠", spoken using the words "Ace of Spades" or represented in different languages including sign languages.

Channel dependent information

In some cases the challenge is to discern meaning from patterns in the communication channel. Examples of this would be:

  • hidden object games where the player needs to visually search and find smaller pictures within a larger visually cluttered image
  • identifying a piece of music from the audio
  • charades
  • reading an alien text using a visual key
  • Any challenge asscociated with discerning between signal and noise.
In these instances the core challenge is intrinsicly linked to the communication channel used. Trying to visualise the audio or sonify the image or video before extracting the meaning from it creates patterns that will not make sense in the new communication channel. Extracting the meaning and then communicating that while visualising or sonifying the communication channel removes the challenge.

We can't make accessibility related adjustments that preserve the core challenge so we must either remove the challenge or replace it with another challenge.

Juicy Design

Juicy design can be seen as a type of intentional friction because it sometimes complicate the communication between the interface and the player. Juice encompasses:

  1. excessive visual and audio feedback on game events and player actions, goals and subgoals
  2. animations and audio designed to mimic real-world effects (eg. camera shake when running, whiteout from explosions)
  3. vibrations triggered by game events or player actions
  4. Distorted sound to mimic the effects of a flashbang or other loud explosion
  5. floating damage numbers or damage indicators
  6. crash zoom or slow motion to emphasise game events

Juice for realism

Juice can sometimes be used to add realism especially for combat-based games. For players with PTSD however too much realism can trigger flashbacks and anxiety. Enabling players to toggle these effects with a suitable level of granularity and potentialy adding trigger warnings at the start of game sessions or play sessions should enable players to choose the experience that suits them.

Other types of Juice

Juice is intended to improve the feel of the game and although it should always agree with the aesthetic and standard communication (juice may be superfluous to the game feedback but should never be at odds with it) any extra communication can increase the cognitive load on players. It can also bury audio and visual cues that inform the player in the juicy feedback that was intended to enhance the experience.

Juice is designed to be superflous so it is intentional friction that can be safely removed when needed without breaking the challenge of the game. By offering options to turn off specific features with appropriate levels of granularity an accomodation can be made without breaking gameplay or making the game less engaging for others.

Glossary

ASD
Autistic Spectrum Disorder is a lifelong neurodevelopmental condition that affects how a person thinks, communicates, behaves, and interacts with the world.
Designed challenge
A level of difficulty intended by the game designer. See experienced difficulty.
Experienced difficulty
The level of difficulty experienced by the user as a result of the interaction between the barriers faced and the user's capabilities.
Flow
The flow state is the optimal experince between the boredom of too little challenge and the anxiety of too much challenge.
Generative friction
Intentional friction that creates a positive user experience. See also protective friction
Juice
Juice refers to audiovisual content (often animations and sound efects) that is unneccessary to be able to play the game but make the game more engaging to players. It is a wide and often loosely defined category that can range from elements that enhance realism to elements that convey a cartoonish or hyperstimulating effect.
Juicy design
Juicy design describes design decisions that contribute the the games juice.
Noise
Part of a representation that doesn't carry meaning in the desired context. See signal.
PTSD
Post Traumatic Stress Disorder is a disorder where a person has had a traumatic experience and things that remind them of this experience can trigger anxiety and flashbacks. It is often associated with warzones but can be linked to any sufficiently traumatic experience.
Protective friction
Intentional friction that avoids a negative user experience. See also generative friction
Signal
Part of a representation that carries meaning in the desired context. See noise.
